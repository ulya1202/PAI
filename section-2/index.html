  • ▶🎲 Random Variableclick me!

    A [[rv|random variable]] is a number that comes from a random event.

    It works like a rule: it looks at what happened (the [[outcome|outcome]]) and gives it a number.

    Example: we flip 2 coins. All outcomes: [[omega|Ω]] = {HH, HT, TH, TT}.
    Our question: "How many heads?" We call this number X. X can be 0, 1 or 2. We don't know it before the flip, and that's why it is random.

    🔑 Trick: "X = 1" is an [[event|event]]: {HT, TH}. And when we have an event, we can find its [[prob|probability]]: P(X = 1) = 2/4 = 1/2.

    How is it different from the variables we know?

    ExampleValue
    Math variablex + 3 = 5x is always 2
    Programming variableage = 25a box with one value
    Random variableX = number of headsmany possible values, each with a chance

    🌍 Real life: tomorrow's temperature, how many messages you get today, how long you wait for the bus. You don't know the number yet, but you know which numbers are likely.

    🐍 Python code: normal variable vs. random variable
    import random

x = 5                        # normal variable: x IS 5
X = random.randint(1, 6)     # random variable: 1..6, each with chance 1/6
print(X)                     # a different number every time!
    🐍 Python code: 2 coins, X = number of heads
    import random

def flip_two_coins():
    coins = [random.choice("HT") for i in range(2)]
    X = coins.count("H")     # the random variable
    return coins, X

counts = {0: 0, 1: 0, 2: 0}
for i in range(10000):
    coins, X = flip_two_coins()
    counts[X] += 1
print(counts)   # about 2500, 5000, 2500

      • ▶🎯 [[bin|Binomial]]count the yeses

        We do [[n|n]] Bernoulli trials and count the yeses.

        Rules: the trials are [[indep|independent]], and every trial has the same chance p.

        We write: X ~ Bin(n, p). X can be 0, 1, …, n.

        💡 A binomial = n Bernoullis added together. And Bin(1, p) is the same as Ber(p).

        Example: our Palpatine poll! 5 harmless questions, each 50/50 → Bin(5, ½).

        🐍 Python code
        def binomial(n, p):
    # n Bernoullis added together
    return sum(bernoulli(p) for i in range(n))

      • ▶📬 [[pois|Poisson]]rare events

        It counts rare events in a time or a space: emails in 1 hour, typos on one page, cars in 1 minute.

        Its [[param|parameter]] is [[lambda|λ]] (lambda) = the average number of events. We write: X ~ Poi(λ)

        🔑 It is really a binomial! Cut 1 hour into many tiny pieces. In each piece an email comes or doesn't come (that's a Bernoulli). We get many trials (big n) and a tiny chance (small p).
        Poisson is just an [[approx|approximation]] of this binomial, because it is much easier to calculate.
        🐍 Python code
        def poisson_like(lam, n=600):
    p = lam / n          # many tiny pieces, tiny chance
    return binomial(n, p)

print(poisson_like(2))   # emails in one hour, average 2

      Continuous = values you measure. It can be any number in a range.

      If you ask "how much? how long?", it is usually continuous. Examples: height, time you wait for the bus, temperature.

      📏 Is your height 172 cm? Take a better ruler: 172.3 … 172.31 … 172.311 … You can always zoom in more. Maybe you are 0.000001 cm taller! There is no "next number" after 172.3. Between any two numbers there are always more numbers, so we can't count the values.

      ⚠️ So the chance of one exact value (exactly 172.311111… cm) is 0.🛑 This branch stops here for now. Instead, we ask about a range: "What is the chance that the height is between 165 and 175 cm?"

  • ▶⚙️ [[pmf|PMF]] · [[pdf|PDF]] · [[cdf|CDF]]: they are all functions!click me!

    First: what does a function do?

    A [[func|function]] is a rule. A value goes in (the [[input|input]]), the rule changes it, and another value comes out (the [[output|output]]). It is the same in math and in programming.

    • Math, linear: f(x) = 2x + 1 → f(3) = 7
    • Math, logarithmic: f(x) = log₁₀(x) → f(100) = 2
    • Programming: def f(x): return 2*x + 1
    • Life: a kitchen machine: apples in → apple pie out 🥧
    PMF, PDF and CDF are also just functions! Nothing magic. The only special thing is the input and the output:
    a value of X goes in → a probability comes out.

    Different from a normal function: 1) the output is always between 0 and 1; 2) all the outputs add up to 1.

    🐍 Python code: a normal function vs. a probability function
    def f(x):                 # a normal math function
    return 2 * x + 1

def pmf_two_coins(k):     # a probability function (PMF)
    table = {0: 0.25, 1: 0.50, 2: 0.25}
    return table.get(k, 0)

print(f(3))               # 7
print(pmf_two_coins(1))   # 0.5

      • ▶🪙 Bernoulli PMFthe simplest formula
        P(X = 1) = p    P(X = 0) = 1 − p

        Short form, one line:

        P(X = k) = pk · (1 − p)1 − k,   k = 0 or 1

        Check: k = 1 → p¹ · (1−p)⁰ = p ✔   k = 0 → p⁰ · (1−p)¹ = 1 − p ✔

        🐍 Python code
        def bernoulli_pmf(k, p):
    return p if k == 1 else 1 - p
      • ▶🎯 Binomial PMFC(n,k) · pᵏ · (1−p)ⁿ⁻ᵏ
        P(X = k) = [[comb|C(n, k)]] · pk · (1 − p)n − k

        What each piece means, in words:

        • pk: k answers are "yes"
        • (1 − p)n − k: all the other answers are "no"
        • C(n, k): how many different ways we can place k yeses among n trials. C(n, k) = n! / (k! · (n − k)!), where [[fact|k!]] = 1·2·…·k
        🐍 Python code
        from math import comb

def binomial_pmf(k, n, p):
    return comb(n, k) * p**k * (1 - p)**(n - k)

print(binomial_pmf(5, 5, 0.5))   # 1/32 = 0.03125
        🧮 Calculator

      • ▶📬 Poisson PMFcomes from the binomial
        P(X = k) = λk · [[e|e]]−λ / k!

        This formula comes from the binomial. When n is big and p is small, the binomial formula is very hard to calculate. So mathematicians made it simpler. It's an [[approx|approximation]]: almost the same answer, much less work.

        We only use λ = n · p (the average), so we don't even need to know n and p!

        ⭐ Optional: where does the formula come from?

        Why is the binomial so bad here? Let's try n = 1000, p = 0.009, k = 5:

        Step by step, from binomial to Poisson:

        Step 1. The average is λ = n · p, so p = λ / n. Replace p with λ/n:

        C(n, k) · (λ/n)k · (1 − λ/n)n − k

        Step 2. Split it into pieces:

        [ n(n−1)…(n−k+1) / nk ] · (λk/k!) · (1 − λ/n)n · (1 − λ/n)−k

        Step 3. Now make n very big:

        • n(n−1)…(n−k+1) / nk → 1 (e.g. 1000·999·998 / 1000³ ≈ 1), so it goes away
        • (1 − λ/n)n → e−λ (a famous limit, see the table below)
        • (1 − λ/n)−k → 1, because λ/n is tiny, so we delete it

        Step 4. What is left:

        P(X = k) ≈ λk · e−λ / k! ✅
        🐍 Python code
        from math import exp, factorial

def poisson_pmf(k, lam):
    return lam**k * exp(-lam) / factorial(k)

print(poisson_pmf(5, 9))     # 0.0607...

      CDF = Cumulative Distribution Function. It works for both discrete and continuous.

      F(x) = P(X ≤ x)

      "What is the chance that X is x or less?" It adds up all the chances from the left.

      def cdf(x, pmf_table):

print(cdf(2, die))    # 2/6 = 0.333

    The expected value is the average value we get if we repeat the random event many, many times.

    It is also called the [[wavg|weighted average]]: every value is multiplied by its chance (its "weight"), and then we add everything.

    E[X] = Σ k · P(X = k)

    Normal average vs. weighted average: the normal average of a die is (1+2+3+4+5+6)/6 = 3.5, and every value has the same weight. When the chances are not equal, the values with a bigger chance count more.

    🎮 A game: you win $10 with chance 0.1, and $0 with chance 0.9.
    E[X] = 10 · 0.1 + 0 · 0.9 = $1. If the game costs more than $1, you lose money in the long run! 😄
    ⚖️ Picture: bars are weights on a beam. E[X] is the point where the beam balances.
    🐍 Python code
    die = {1: 1/6, 2: 1/6, 3: 1/6, 4: 1/6, 5: 1/6, 6: 1/6}
E = sum(k * prob for k, prob in die.items())
print(E)    # 3.5

    • ▶🪙 Bernoulli: E[X] = pwhy?
      E[X] = 1 · p + 0 · (1 − p) = p

      Why it makes sense: if it rains with chance 0.3, then over many days, it rains on about 30% of them. The average of all the 1s and 0s is 0.3.

    • ▶🎯 Binomial: E[X] = n · pwhy?

      A binomial is n Bernoullis added together, and each one has average p:

      E[X] = p + p + … + p (n times) = n · p

      Example: 5 harmless questions, each 50/50 → 5 · ½ = 2.5 yeses on average. That's our number from the Palpatine poll!

    • ▶📬 Poisson: E[X] = λwhy?

      Poisson is a binomial with p = λ/n, so:

      E[X] = n · (λ / n) = λ

      That's why λ is called "the average number of events".

  • ▶📏 [[var|Variance]] & [[sd|Standard Deviation]] ⭐ Optionalclick me!
    ⭐ Optional: this chapter is extra. You don't need variance or SD for the Palpatine problem.

    The expected value tells us where the center is. But two random variables can have the same center and still be very different!

    • A: always 5
    • B: 0 or 10, 50/50

    Both have E = 5, but B jumps around much more. Variance measures this spread.

    Var(X) = E[(X − μ)²]

    "On average, how far are the values from the center ([[mean|μ]]), squared?"

    An easier way to calculate it:

    Var(X) = E[X²] − (E[X])²
    📏 From variance to standard deviation: variance has squared units (cm²), so it is hard to understand. So we take the square root:
    SD(X) = σ = √Var(X)
    Now it has the same units as X. Read it as: "the values are usually about σ away from the average".
    ↔️ Same center, different spread
    Distance from 5:
    ▼ mean
    Purple bracket = from mean − SD to mean + SD
    • ▶🎲 Example: one diestep by step

      1. E[X] = (1+2+3+4+5+6)/6 = 3.5

      2. E[X²] = (1+4+9+16+25+36)/6 = 91/6 ≈ 15.17

      3. Var(X) = 15.17 − 3.5² ≈ 2.92

      4. SD = √2.92 ≈ 1.71

      🐍 Python code
      die = {k: 1/6 for k in range(1, 7)}
E   = sum(k * p for k, p in die.items())       # 3.5
E2  = sum(k**2 * p for k, p in die.items())    # 15.17
var = E2 - E**2                                # 2.92
sd  = var ** 0.5                               # 1.71
print(E, var, sd)

  • ▶📖 [[model|Probabilistic Model]]click me!

    A probabilistic model is a story that makes data. 📖

    The story uses random variables, and each one has [[param|parameters]]: the "knobs" of the story, like p, n or λ.

    With a story we can do 2 things:

    1. Make fake data ([[sim|simulation]]): run the story on a computer many times, then count.
    2. Find the knobs: turn the knobs until the fake data looks like the real data.
    🚀 Our Palpatine poll story, for one person:
    • harmless yeses: H ~ Bin(5, ½)
    • Palpatine secret: S ~ Ber(p) ← the knob we want
    • answer = H + S (and a 0 becomes a 1)

    👉 Try it on the right: move p and look at the bars. When do the two charts look the same? (Bonus: also compare the averages.) And look at the bar at 0!

    🐍 Python code: the Palpatine story
    import random

def one_answer(p):
    H = binomial(5, 0.5)      # harmless yeses
    S = bernoulli(p)          # secret: supports Palpatine?
    answer = H + S
    if answer == 0:           # nobody says 0
        answer = 1
    return answer

fake = [one_answer(0.1) for i in range(1000)]
print(sum(fake) / 1000)       # compare with the real average

    • ▶1️⃣ Make fake datathe coffee shop ☕

      Story: "Every customer buys coffee with chance p. A person who buys coffee also buys a cake with chance q."

      We run the story for 1000 customers and count. Now we can answer questions like "How many cakes should we bake tomorrow?"

      🐍 Python code
      import random

def one_customer(p, q):
    coffee = random.random() < p                # Bernoulli(p)
    cake = coffee and random.random() < q       # Bernoulli(q), only if coffee
    return coffee, cake

customers = [one_customer(0.7, 0.3) for i in range(1000)]
cakes = sum(cake for coffee, cake in customers)
print("Cakes sold:", cakes)    # around 1000 * 0.7 * 0.3 = 210
      p (coffee)
      q (cake)
    • ▶2️⃣ Turn the knobsfake ≈ real

      Usually we don't know the parameters. But we have real data. So we:

      1. Guess the parameters
      2. Run the story → fake data
      3. Compare fake data with real data
      4. Adjust (turn the knobs) until fake ≈ real

      That's exactly what we did with Palpatine: we moved the slider until the fake bars looked like the real bars → p ≈ 0.1. 🎉 (Bonus: the averages match there too.)

      Small differences in the second decimal are [[noise|sampling noise]]: another 1000 people would wobble a little.

    • ▶3️⃣ Later: the computer does ittraining 🤖

      Today we turned the knob by hand. Later in the course, the computer will do it by itself.

      For every possible p, the computer asks: "If my story is true with this p, how likely is the real data?" Then it picks the p that makes the real data most likely. This is called [[mle|Maximum Likelihood]].

      When a computer finds the best parameters of a model from data, we call it [[train|training]]. So today, you trained a model by hand! 🎉

The 6 questions are not the same: 5 have chance ½, and 1 has chance p.

A binomial needs the same chance in every trial. So one Bin(6, ?) is wrong. We put each group in its own random variable.

Bonus: now the unknown p sits alone in S. It is the only knob we turn. 🎛️

2️⃣ Wait… why do we add them?

😇 H: ?
🤫 S: ?
🗣️ what we hear

Because the person adds them in their head and tells us only the total. Our story must make data the same way the real people do: answer = H + S.

After adding, the colors are mixed: from one number you can't see which yes was the secret. The sum is what hides the secret! 🛡️

3️⃣ Wait… why does a 0 become 1?

Blue = our story · = real data · orange = the moved zeros

Look at the real data: the bar at 0 is empty. Why? Saying 0 means "all no", also the secret one. Palpatine would know you said "no" → 🪓! So people who had 0 say 1.

Our story without the rule makes about 3% zeros, a bar the real data doesn't have. 🚫 A story must make data exactly the way the real data was made, so we copy the rule: if answer == 0: answer = 1

4️⃣ Wait… why do we subtract 2.5? ⭐ Bonus

This is the math shortcut, with no simulation. The average of a sum = the sum of the averages:

E[H + S] = E[H] + E[S] = 5 · ½ + p = 2.5 + p

Each harmless question adds ½ to the average. Everybody gets these 2.5, so they tell us nothing. We remove them (and the tiny bit from the 0 → 1 rule), and p is what's left!

5️⃣ Wait… why 1000 fake people?

Fake people in one run:

Every run gives a slightly different average (1 dot = 1 run). This is sampling noise.

👉 N = 10: the dots are everywhere. With 10 people, p = 0.09 and p = 0.3 look the same!
👉 N = 1000: the dots stay close together. Now the average really tells us p.

The real data has 1000 people. We make 1000 fake people too: same size, same amount of noise, bars you can compare. A fair comparison! ⚖️
